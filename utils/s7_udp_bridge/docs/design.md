# S7-to-UDP (Any-to-Any) 万能点位映射桥接器设计说明书

## 1. 概述与降维打击背景

在分布式计算架构中，西门子 S7-1200 等低端 PLC 的核心职责应当被简化为纯粹的 **IO采集与底层输出驱动器**，而复杂的电梯调度、多部电梯协同、高维状态机控制逻辑应当被解耦并运行在性能强大的上位机（Linux / Python 节点）中。

然而，传统的 TIA 编程中，PLC 的以太网协议栈十分脆弱，通过内置 `TUSEND` 高频、突发、密集地向外广播 UDP/TCP Bitmap 极易触发 TIA 底层的 TCP/IP 缓存溢出或死锁，进而导致 PLC 协议栈崩溃。

**本工具的设计目的：**
通过运行在 Linux 上位机（或临近边缘节点）的轻量级 Python 守护进程，使用最稳健、工业界最为广泛接受的 **S7 协议（基于 TCP 102 端口）** 去 **主动高频轮询（Poll）** PLC 的状态，并在上位机内存中将读取到的点位直接转换成 100 字节（800 个 I点位）的 UDP Bitmap 广播，从而伪造出 PLC “主动 UDP 上报”的景象。
这种设计不仅消除了 PLC 本身发包的网络压力，还实现了上位机控制层分布式软件的 **“零代码更改平滑迁移”**。

## 2. 物理与逻辑映射架构 (Any-to-Any)

为了应对比赛现场裁判组可能临时追加、修改物理点位，或者将数据从 `DB10` 飘移到 `DB11`，甚至需要对物理输出 `Q` 点（用于动作闭环监控）及内部存储位 `M` 进行提取注入的恶劣实况，本桥接器支持 **任意物理点位到 100 字节 UDP Bitmap 任意 Bit 索引的投射**。

### 2.1 100字节 UDP Bitmap 协议规范
- **包大小**：固定 100 字节（二进制形式直接发送，无额外帧头尾）。
- **位宽**：100 字节 $\times$ 8 = 800 个 Bit，逻辑上对应上位机分布式框架里的输入引脚 `I0.0` 到 `I99.7`。
- **映射规则**：在 UDP 报文第 `N` 字节（$0 \le N \le 99$）的第 `K` 位（$0 \le K \le 7$），其代表上位机的虚拟输入信号 `I{N}.{K}`。当对应 Bit 设为 `1` 时，代表引脚高电平；设为 `0` 时，代表引脚低电平。
- **存储顺序**：按照小端或原生字节流直接切片。

## 3. 配置文件规范 (`config.ini`)

配置文件应存放在 `utils/s7_udp_bridge/config.ini`，具备以下三大核心配置段：

```ini
[plc]
# PLC 硬件连接信息
ip_address = 192.168.1.8
port = 102
rack = 0
slot = 1

[udp]
# 目的上位机监听端地址和端口（即 daemon_gpio.py 监听的 read_port）
dest_ip = 127.0.0.1
dest_port = 11451

[polling]
# 轮询时间间隔，单位：毫秒。建议设为 50ms (或根据比赛现场网络响应调大至 10-100ms)
interval_ms = 50

[bit_mappings]
# ----------------------------------------------------
# 比特粒度批量映射（主力映射，对人类最友好的写法）
# ----------------------------------------------------
# 只需填 3 个 Key，自动算出末位对应（不要再数逗号、一行太长、读错位）：
#   Start_Mapping_I   = 目的起点（UDP 虚拟 I 点位）
#   Start_Mapping_DB  = 源起点（PLC 物理点位，仅支持 DB）
#   Mapping_Count     = 位数（1~800）
#
# 下面代表：把 DB10.DBX0.0 起的 223 个位映射到 UDP Bitmap 的 I2.0 起的 223 个位
# 自动计算末位对应关系：
#   源 linear 0..222   →  DB10.DBX0.0 .. DB10.DBX27.6
#   目的 linear 16..238 → I2.0 .. I29.6
Start_Mapping_I  = I2.0
Start_Mapping_DB = DB10.DBX0.0
Mapping_Count    = 223

# 多条连续块（备选；用了上方 [Start_*] 三 Key 后，本段内同格式不再解析）：
# bit_map_1 = DB10.DBX0.0, I2.0, 223

[db_mappings]
# ----------------------------------------------------
# 字节粒度批量映射（备选；与 bit_mappings 并存时 bit_mappings 优先级更高）
# ----------------------------------------------------
# 语法：任意键名 = DB号, PLC起始字节, 读取长度(字节), 填充到UDP_Bitmap的起始字节
#
# 范例：一次性读取 DB10.DBB0 到 DB10.DBB27（共28字节，对应电梯现场全部224个点），
# 直接、无缝复制到 UDP 100字节 的第 0 字节开始（即自动投射到上位机虚拟输入 I0.0 - I27.7）
# db_map_1 = 10, 0, 28, 0

[fine_mappings]
# ----------------------------------------------------
# 精细单个点位自由映射（完美支持任意区域点位跨界投射）
# ----------------------------------------------------
# 语法：PLC物理点位 = 上位机虚拟I点 (格式固定为 I{byte}.{bit})
#
# 1. 支持 DBX 点临时跨界、不规则飘移映射：
DB11.DBX12.4 = I10.3   ; 将 PLC 中的 DB11.DBX12.4 状态映射到 UDP 报文的 I10.3 (即第10字节第3位)
# 2. 支持物理输出 Q 点监控（比如在上位机闭环中，验证物理接触器、接触阀是否真正得电动作）：
Q0.0 = I28.2           ; 将 PLC 物理输出 Q0.0 状态映射到 UDP 报文的 I28.2
# 3. 支持内部状态位 M 点监控：
M4.5 = I28.3           ; 将 PLC 内部存储位 M4.5 状态映射到 UDP 报文的 I28.3
# 4. 支持单个物理输入 I 点飘移重写：
I1.2 = I28.4           ; 将 PLC 物理输入 I1.2 映射到 UDP 报文的 I28.4
```

## 4. 核心优化算法：合并去重读取逻辑

为了绝对避免“多请求拖垮 PLC”的弱智设计，桥接器在启动加载阶段应在内存中做**合并去重**：

### 4.1 初始化与合规性检查（只在启动时运行一次）
1. **初始化缓冲区**：创建一个长度为 100 的全局 `bytearray` 数组，作为 UDP Bitmap 发送缓冲区：`udp_buffer = bytearray(100)`。同时创建 `last_good_bitmap = bytearray(100)` 作为断线兜底。
2. **解析 `bit_mappings`**（主力）：
   - 提取所有比特粒度批量映射。每条任务格式：`(src_area, src_db, src_byte, src_bit, count, udp_byte, udp_bit)`。
   - 解析左值（PLC 物理点位）用与 fine_mappings 同一套点名字典；右值统一是 `I{byte}.{bit}` 格式。
   - **运行期静默截断**：若 `udp_byte*8 + udp_bit + count > 800`，则把 `count` 截断到刚好填满 100 字节，不抛错、不警告（便于现场临时改配置不致命）。
   - 把每条 bit_mapping 的源字节覆盖区间 `[src_byte, src_byte + ceil((src_bit+count)/8))` 登记到全局"批量覆盖区间表"。
3. **解析 `db_mappings`**（备选字节批量）：
   - 提取所有批量映射任务。每个任务格式为：`(db_number, plc_start, length, udp_start)`。
   - 验证其字节范围，保证 `udp_start + length <= 100`，越界则同样静默截断 `length`。
   - 把覆盖区间 `[plc_start, plc_start+length)` 登记到全局"批量覆盖区间表"。
4. **解析并合并 `fine_mappings`**：
   - 将所有精细映射的键（如 `DB11.DBX12.4`）解析为 PLC 寻址元组：`(Area, db_number, byte_idx, bit_idx)`。
     - 区域映射对照：
       - `DB{n}.DBX{y}.{z}` $\rightarrow$ `Area.DB`, `db_number=n`, `byte=y`, `bit=z`
       - `Q{y}.{z}` $\rightarrow$ `Area.PA`, `db_number=0`, `byte=y`, `bit=z`
       - `I{y}.{z}` $\rightarrow$ `Area.PE`, `db_number=0`, `byte=y`, `bit=z`
       - `M{y}.{z}` $\rightarrow$ `Area.MK`, `db_number=0`, `byte=y`, `bit=z`
   - 将精细映射的值（如 `I10.3`）解析为目标 UDP 坐标：`(udp_byte, udp_bit)`。
   - **内存缓存穿透优化**：
     - 精细点位的源 `(Area, db_number, byte_idx)` 只要落在"批量覆盖区间表"中任意一条 bit_mapping 或 db_mapping 范围内 → 标记 `cache_source=True`。
     - 在高频轮询时，这类点位**直接在内存中读取批量读取的结果，完全不向 PLC 发起单独读取请求**。
     - 对于没有落在覆盖范围内的精细点位，将其按 `(Area, db_number, byte)` 分组，形成一个"去重后的精细单字节读取清单"。

---

### 4.2 高频轮询主循环（以 50ms 频率循环）

```
  +-------------------------------------------------------------+
  |                      开始一轮 polling 循环                  |
  +-------------------------------------------------------------+
                                 |
                                 v
  +-------------------------------------------------------------+
  |              初始化当前轮 buffer：tmp_buffer = [0x00]*100   |
  +-------------------------------------------------------------+
                                 |
                                 v
  +-------------------------------------------------------------+
  | 1. db_mappings 批量读取：执行所有 client.read_area         |
  |    - 将字节块直接写入 tmp_buffer[udp_start:...]              |
  |    - 同时按 (Area.DB, db, byte) 缓存到 byte_cache           |
  +-------------------------------------------------------------+
                                 |
                                 v
  +-------------------------------------------------------------+
  | 2. bit_mappings 批量读取：对每条 bit_mapping 计算源字节长度  |
  |    client.read_area(Area.DB, db, src_byte, src_byte_len)    |
  |    - 按 bit 粒度逐位移入 tmp_buffer 的 udp_byte.udp_bit     |
  |    - 同时缓存源字节到 byte_cache                              |
  |    （此步覆盖 db_mappings：bit 写入比 byte 写入更靠后）      |
  +-------------------------------------------------------------+
                                 |
                                 v
  +-------------------------------------------------------------+
  | 3. 精细读取：遍历"去重后的精细单字节读取清单"               |
  |    - 若该字节在上面步骤 1/2 的 byte_cache 中：直接读缓存      |
  |    - 若不在：调用 client.read_area(..., length=1) 单字节读取  |
  +-------------------------------------------------------------+
                                 |
                                 v
  +-------------------------------------------------------------+
  | 4. 位投射映射：将 fine_mappings 状态提取，映射到目标 bit    |
  |    - cache_source: 从 byte_cache 取字节、get_bool 提值      |
  |    - external: 同样取字节、提值                              |
  |    - 清除或置位 tmp_buffer[udp_byte] 的 udp_bit              |
  +-------------------------------------------------------------+
         |                                               |
    (读取成功)                                        (发生异常)
         |                                               |
         v                                               v
  +-----------------------------+         +-----------------------------+
  | 更新全局 last_good_bitmap   |         | 1. 控制台黄色警告           |
  | = tmp_buffer                |         | 2. 保持 tmp_buffer =        |
  |                             |         |    last_good_bitmap         |
  |                             |         | 3. 标记重连，1.5 秒后尝试重连|
  +-----------------------------+         +-----------------------------+
         \                                               /
          \----------------------┬----------------------/
                                 |
                                 v
  +-------------------------------------------------------------+
  | 4. UDP 发送：向 dest_ip:dest_port 单向发送这 100 字节       |
  +-------------------------------------------------------------+
                                 |
                                 v
  +-------------------------------------------------------------+
  | 5. 极速时钟计算：计算剩余 sleep 时间并等待，进入下一轮       |
  +-------------------------------------------------------------+
```

## 5. 工业级异常处理：“防抖/缓存保持”设计

这是本工具在现场防爆、防摔的重中之重：
- **故障描述**：比赛现场由于大功率接触器瞬时得电产生的强电磁干扰，或者是物理网线松动、交换机突发丢包，极易导致某次 S7 通信读取操作抛出 `Snap7Exception` 超时异常。
- **致命逻辑**（绝对要避免）：如果通信一报错，就把向分布式上位机广播的 UDP Bitmap 全部清零，那么上位机状态机会在 50ms 内认为**电梯所有光电限位开关、平层信号、安全触板瞬间全部消失**，这会导致电梯软件进入崩溃保护或产生剧烈机械晃动，甚至直接撞顶/蹲底。
- **防抖设计**：
  - 维护一个 `last_good_bitmap` 数组，其始终保存**最后一次与 PLC 正常通信时的 100 字节状态**。
  - 一旦捕获到通信异常，**直接沿用、重发 `last_good_bitmap`** 维持状态平稳，防止电平瞬间下跌。
  - 在控制台打印高可见度的报警，并静默将 client 析构，每隔 `1.5 秒` 发起一次非阻塞异步重连，直到 PLC 重现。在此期间上位机分布式程序感知不到任何网络抖动，保障系统安全。

## 6. 现场调试利器：差分日志系统 (`--debug`)

比赛现场 debug 时间只有宝贵的几分钟，满屏的高频轮询日志毫无价值。
- **设计规范**：
  - 小工具默认应保持安静运行，只输出基本的启动、配置加载、连接成功以及致命重连日志。
  - 启动时若带上参数 `python3 bridge.py --debug`，则开启**差分日志（Change-only logging）**：
    - 内存中保留上一轮发送的 `last_sent_bitmap`。
    - 每次轮询仅当 `tmp_buffer != last_sent_bitmap` 时，找出那些**发生变化的特定物理点**，并彩色高亮打印其跳变（例如：`[DEBUG 14:02:10.124] 点位跳变 -> DB10.DBX2.1 (对应虚拟I12.1) : 0 -> 1`）。
    - 这种定向差分打印能让您在现场用手推电梯限位开关时，直接在屏幕上瞬间对齐物理引脚，效率提升百倍。

## 7. 现场极速热部署与验证流程

### 7.1 现场一键部署
1. 进入 `utils/s7_udp_bridge` 目录，执行 Ctrl+C 杀掉残留进程。
2. 运行 `python3 bridge.py` 以前台 debug 方式启动，确认 PLC 连接建立。

### 7.2 一键验证脚本
利用项目中现成的 `debug_utils/new_get.py`：
1. 启动接收端监听：
   ```bash
   python3 debug_utils/new_get.py
   ```
2. 启动中转桥接器：
   ```bash
   python3 utils/s7_udp_bridge/bridge.py --debug
   ```
3. 在 PLC 侧改变 DB10 / DB11 的状态（或断网），观察接收端 `new_get` 输出，验证 100 字节 Bitmap 是否组装正确、映射是否如预期跳变、以及断网时是否稳定不抖动。
